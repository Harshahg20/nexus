### Agent Invocation Approach

**MVP:** `session.sql()` calling `SNOWFLAKE.CORTEX.DATA_AGENT_RUN(...)` — non-streaming JSON response. The `services/agent.py` module wraps this in a clean function that:
1. Constructs the JSON request body
2. Escapes for SQL string embedding
3. Executes via Snowpark session
4. Parses the response JSON
5. Extracts text, tool results, tables, and charts from the content array

The service abstraction is designed so the REST API (streaming) can be swapped in later without changing component code.

### Local Configuration

```toml

account = "..."
user = "..."
authenticator = "externalbrowser"  # or password, keypair
role = "ACCOUNTADMIN"
warehouse = "COMPUTE_WH"
database = "NEXUS_DB"
```

No `.env` files. No credentials in code. A `.streamlit/secrets.toml.example` will be created with placeholder values.

### Design Approach

- Dark theme via Streamlit `set_page_config(layout="wide")` + custom CSS injection for dark professional palette
- Strong typographic hierarchy: large KPI numbers, compact section headers
- Dependency chain rendered as a vertical flow using Streamlit columns/containers with arrow connectors (CSS-styled)
- Mitigation table uses `st.dataframe` with formatted currency columns
- Chat uses `st.chat_message` / `st.chat_input` with session state history
- All scenario outputs display the standard disclaimer

### Risks / Blockers

| Risk | Mitigation |
|---|---|
| `DATA_AGENT_RUN` timeout (15 min default) | Agent queries complete in <30s based on testing; add timeout handling in service layer |
| Agent response parsing complexity | Response schema is well-documented from 7/7 test runs; extract `text` and `table` blocks |
| No streaming chat UX | MVP uses spinner + full response. REST API upgrade path documented in `agent.py` |
| Snowflake connection auth locally | Use `externalbrowser` authenticator for zero-config SSO; document alternatives |

### Team Decision

**Solo execution.** The files are tightly coupled (shared service layer, consistent theming, sequential component dependencies), and coordination overhead for 11 small files exceeds the benefit of parallelism. The dependency chain is: services → components → main app, which is inherently sequential.
